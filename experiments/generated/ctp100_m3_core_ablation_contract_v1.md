# CTP100 M3 两项核心消融实验冻结协议 v1

> 状态：已在实现和查看新实验结果之前冻结。冻结日期：2026-09-06。
>
> 机器可读版本：`experiments/generated/ctp100_m3_core_ablation_contract_v1.json`。
>
> 这一文件只规定“实验要比较什么、使用哪些数据、哪些条件下不能开跑”。本任务不实现消融、不调用大模型，也不产生实验结果。

## 1. 这两项实验分别回答什么

### A1：结构化目标状态是否有用

- 保留机制的方法：`adaptive_multi_agent_no_reuse`，论文中写作 **M3-no-reuse**。
- 删除机制的方法：`adaptive_multi_agent_no_state`，论文中写作 **M3-no-state**。
- 唯一希望考察的核心差异：有没有显式、结构化的跨轮目标状态。

为什么 M3-no-state 不直接只和完整 M3 比：完整 M3 除了有目标状态，还会复用上一轮 Agent 和工具结果。若直接把二者作为唯一比较，就无法判断结果变化来自“状态表示”还是“结果复用”。因此，A1 的主比较固定为：

`M3-no-reuse（有结构化状态、无结果复用）` 对 `M3-no-state（无结构化状态、无结果复用）`。

完整 M3 只能作为补充背景，不能替代这个主比较。

### A2：下游失效传播是否有用

- 保留机制的方法：`adaptive_multi_agent`，论文中写作 **M3-full**。
- 删除机制的方法：`adaptive_multi_agent_no_propagation`，论文中写作 **M3-no-propagation**。
- 唯一希望考察的核心差异：上游结果变化时，是否继续让依赖它的下游旧结果失效并重算。

M3-no-propagation 仍然保留目标状态、变化槽位识别、动态调度、结果复用、复用有效性检查以及缺失上游结果补全。它只关闭“由于上游重算或失效，继续让下游旧结果失效”这一步。

## 2. 四个相关方法的边界

| 方法 | 结构化跨轮状态 | 动态调度 | 依赖补全 | 下游失效传播 | 历史结果复用 | 在本实验中的角色 |
| --- | --- | --- | --- | --- | --- | --- |
| M3-full | 有 | 有 | 有 | 有 | 有 | A2 的完整方法参照 |
| M3-no-reuse | 有 | 有 | 有 | 有 | 无 | A1 的匹配参照，已有结果 |
| M3-no-state | 无 | 有，但只能按当前可见文字做无状态路由 | 有 | 无 | 无 | A1 新消融 |
| M3-no-propagation | 有 | 有 | 有 | 无 | 有 | A2 新消融 |

### M3-no-state 允许看见什么

它可以看见当前用户话语，以及该方法自己产生的普通 `role/content` 对话文字。这样用户第二轮说“其他不变”时，系统至少还拥有普通聊天上下文。

它不能获得：

- `method_previous_state`；
- `previous_slots`、合并后的 `current_slots`；
- `changed_slots`、`preserved_slots`；
- `GoalStateTaskTicket`；
- 上一轮结构化输出、Agent 输出和工具结果；
- 金标或评价器专用字段。

保留自然语言历史并不等于保留结构化状态。若连对话文字也删除，实验测到的将是“有没有聊天记忆”，而不是“结构化目标状态有没有价值”。

### M3-no-propagation 到底关闭什么

先区分两个概念：

1. 直接失效：某个用户条件变化后，直接负责该条件的 Agent 结果失效。
2. 传播失效：上游 Agent 需要重算后，依赖它的下游旧结果也随之失效。

冻结的传播关系为：

- 景点结果变化，可以传播到行程和预算；
- 天气结果变化，可以传播到行程。

M3-no-propagation 保留第 1 类，删除第 2 类。删除传播后仍复用到可能已经陈旧的下游结果，是这项消融有意制造的机制缺口，并不是程序错误。

## 3. 直接失效与传播失效的冻结拆分

为了避免实现阶段根据实验成绩临时解释“什么算传播”，现在先把规则定死。

| 变化内容 | 直接失效的 Agent | 完整 M3 再通过传播增加的 Agent |
| --- | --- | --- |
| 目的地 | 景点、天气、行程、预算 | 无，四者都直接受目的地影响 |
| 行程天数 | 天气、预算 | 行程 |
| 出发日期 | 天气、预算 | 行程 |
| 人数 | 行程、预算 | 无 |
| 游客类型 | 景点 | 行程、预算 |
| 偏好 | 景点 | 行程、预算 |
| 特殊要求 | 景点 | 行程、预算 |
| 预算金额/档次 | 预算 | 无 |
| 天气情景 | 天气 | 行程 |
| 出发地 | 默认预算；若任务票据明确要求，则为行程和预算 | 无 |
| 明确要求按新预算重排行程 | 行程、预算 | 无 |
| 已有天气可复用时的天气调整 | 行程、预算 | 无 |
| 明确全部重做或无法识别的变化 | 景点、天气、行程、预算 | 无 |

实现时允许把现有代码重构为“直接失效集合 + 传播增加集合”，但必须满足：打开传播时，M3-full 最终的计划 Agent、复用 Agent 和失效 Agent 与重构前一致。否则改动已经改变完整方法，不再是合法消融。

## 5. 新增实验规模

每个新方法都完整运行 30 个双轮场景，重复 3 次：

```text
30 场景 × 2 轮 × 3 次 = 每个方法 180 条原始结果
2 个新方法 × 180 条 = 新增 360 条原始结果
```

主要评价只看第二轮：

```text
30 个 t2 × 3 次 = 每个方法 90 条目标轮结果
2 个新方法 × 90 条 = 180 条新增目标轮结果
```

重复编号固定为 `0、1、2`。每一种方法的第二轮只能读取该方法自己的第一轮信息，而且必须遵守该方法自己的状态可见范围。

## 7. 指标和论文表述范围

主要指标固定为 30 个第二轮场景上的 STSR，统计单位是 `scenario_id`，不能把 3 次重复后的 90 行假装成 90 个互相独立的旅游案例。

次要质量指标包括 HCSR、ITCSR、未修改槽位保持率、Agent 集合精确匹配率和工具集合精确匹配率。效率指标包括 Agent/工具调用数、Token、标准化估算成本和时延。

第一轮结果、60 轮混合汇总以及 13 个传播候选题的子集结果只能作描述性分析。论文结论只能表述为“在冻结的 CTP100 双轮受控基准上观察到的机制效果”，不能扩大为所有旅游对话或其他领域上的普遍结论。

## 8. 所有方法必须保持相同的内容

- 模型：`gpt-5-mini`
- 温度：`0`
- 最大输出：`4096 tokens`
- 推理强度：`minimal`
- 相同的四个业务 Agent：景点、天气、行程、预算
- 相同的三个生成工具：景点检索、天气查询、预算计算
- 相同 Prompt、工具代码、工具顺序、冻结数据和评价器
- 相同超时、重试、失败分类和失败保留规则
- 金标与评价字段都不能进入生成阶段

不得修改题库、金标、评价器、业务 Agent Prompt、天气/预算/城际交通等数据来改善消融成绩；不得使用 mock 静默兜底；不得只重跑失败行并替换原结果。

## 9. 后续实现前的硬门禁

出现以下任何一种情况，都不能调用正式大模型：

- 选出的不是 30 个场景或 60 个轮次；
- 已有比较数据缺失或哈希变化；
- 打开传播时，重构后的完整 M3 调度结果与原版不一致；
- M3-no-state 仍收到结构化上一轮状态；
- M3-no-propagation 的实际传播机会为 0；
- 金标或评价器字段进入生成输入；
- 实现没有测试、Git 工作区不干净或尚未建立冻结标签。

正式运行结束后还要检查：新增结果恰好 360 条、每种方法恰好 180 条、重复编号为 0/1/2、键值无重复、第二轮状态来源合法，并且 trace、worker I/O、checkpoint、manifest、门禁报告和最终索引全部完整。
